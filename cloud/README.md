# Проверка камеры с Railway

Отдельный одноразовый сервис `tourism-camera-probe` в существующем проекте.
Репозиторий: `mikhailelagov/thai-tourism-dashboard`, ветка `railway-camera-pilot`,
корневая папка `/cloud`, Dockerfile. Команда по умолчанию: `python /app/health.py`.
Расписания нет; после проверки процесс завершается. Секреты и публичный адрес не нужны.

`health.py` открывает только синтетическую страницу в памяти браузера и проверяет
его работу. Внешние страницы и камеры при этом не открываются.

## Цель и границы исследования

24 сентября пользователь уточнил: это личное некоммерческое исследование
колебаний туристической активности. Нужны только численные результаты подсчёта,
время и качество замера. Хранить видео и снимки пользователь не хочет.
Прежняя характеристика задачи как бизнес-аналитики была предположением ассистента.

Первую попытку запуска `probe.py` отклонила автоматическая проверка из-за этого
предположения. После уточнения цели разрешён повторный одноразовый тест обычного
просмотра публичного плеера: без скриншотов, записи, скачивания видеофайлов и
обхода защиты. Это не разрешение на запись изображений и не юридическое заключение
о любых вариантах автоматического анализа. Условия: https://livestream.pattaya.go.th/terms.

Для технической проверки без расширения прав GitHub App используется официальный
образ `mcr.microsoft.com/playwright/python:v1.58.0-noble`, лимиты 1 vCPU/1 GiB,
политика перезапуска Never. Команда скачивает только закреплённую версию нашего
публичного скрипта и проверяет SHA-256 до исполнения. Для `health.py` общий лимит
120 секунд, для проверки плеера — 210 секунд с установкой зависимостей;
сам просмотр ограничен 120 секундами.
Полноценный сборщик впоследствии следует собирать из Dockerfile.

## Проверка камеры

Фактический результат в `camera-probe-result.json`: 24 сентября в 14:53 по
Бангкоку страница открылась с кодом 200, камера SC-088 выбрана обычным интерфейсом,
но запрос плеера `/api/public-stream/...` получил 403. Видеоэлементов — 0.
Подсчёт недоступен; ноль людей не записывается. Тест завершён, расписания нет.

Обычный Chromium открывает публичную страницу и выбирает только SC-088 Бали Хай.
Проверяются два состояния видео с интервалом 20 секунд. Общий лимит — 120 секунд.
Защита сайта не обходится, условия не принимаются автоматически.
В журнале Railway появляется `probe_result`: разрешение, продвижение видеочасов,
ошибки HTTP без параметров URL, CPU и максимальная память дочернего процесса.
Показатель памяти — измерение процесса, не точный счёт Railway.

Это проверка транспорта, **ещё не подсчёт людей и не работающий пятиминутный сбор**.
`people: null` всегда; прогресс видеочасов не доказывает движение в сцене или
абсолютную свежесть камеры. Видео и снимки не сохраняются.

После успешного доступа нужна отдельная проверка качества подсчёта в согласованной
пешеходной зоне, затем журнал на постоянном диске и ограниченный недельный запуск.
При отказе доступа сохраняется причина, бесконечные повторы не запускаются.

Проверка логики: `python3 -m unittest discover -s cloud -p 'test_*.py' -v`.
