# Thailand Tourism Demand

Двуязычная (EN/RU) сводка спроса на туризм по шести направлениям Таиланда:
сайт + Telegram-бот, которые работают от одних и тех же данных.

Всё обновляется автоматически раз в сутки. Руками вписывать ничего не нужно.

```
GitHub Actions (раз в сутки)
        │
        ├─ build_data.py  →  data.json  →  сайт (GitHub Pages)
        │
        └─ send_telegram.py           →  сообщение в Telegram
```

## Что подтягивается само

| Данные | Источник | Ключ |
|---|---|---|
| Погода, 8 дней, 6 точек | Open-Meteo | не нужен |
| Курсы валют | ExchangeRate-API | не нужен |
| Праздники Таиланда | Google Calendar (iCal) | не нужен |
| Праздники стран-доноров | Google Calendar — CN, RU, IN, MY, KR, GB, DE, AU | не нужен |

Праздники Таиланда — самый важный календарь, и `date.nager.at` его **не покрывает**
(отдаёт пустой ответ для TH, IN, MY). Поэтому используются публичные iCal-фиды Google.

## Что не автоматизируется

Честно, чтобы не было сюрпризов:

- **Загрузка отелей** — открытого API нет ни у кого. Только отчёты ассоциаций раз в месяц.
- **Статистика приездов TAT** — публикуется пресс-релизами, не потоком данных.
- **Рыночный сюжет** (топливо, сокращение рейсов, прогноз на год) — это связывание
  фактов, а не показатель. Живёт в константах `index.html` и помечен своей датой.

Первые два меняются помесячно, так что ежедневная сводка от них не зависит.

## Настройка — один раз

### 1. Репозиторий

Создать репозиторий на GitHub и залить туда эту папку.

### 2. Бот

Написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
Затем узнать свой chat id: написать боту любое сообщение и открыть
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` — нужное число лежит в `chat.id`.

### 3. Секреты

**Settings → Secrets and variables → Actions → Secrets:**

- `TELEGRAM_BOT_TOKEN` — токен от BotFather
- `TELEGRAM_CHAT_ID` — ваш chat id

**Вкладка Variables** (необязательно):

- `DASHBOARD_URL` — адрес сайта, добавит ссылку в сообщение
- `SUMMARY_LANG` — `ru` (по умолчанию) или `en`

Токен нигде в коде не хранится — скрипт читает его из окружения.

### 4. Сайт

**Settings → Pages → Source: Deploy from a branch → `main` / `root`.**

Задача коммитит свежий `data.json` в репозиторий, Pages его раздаёт.

### 5. Проверка

**Actions → Daily tourism summary → Run workflow.** Первый запуск можно
не ждать до утра.

## Расписание

`0 1 * * *` — 01:00 UTC, то есть 08:00 по Бангкоку. Меняется в
`.github/workflows/daily.yml`.

## Локальный запуск

```bash
python3 scripts/build_data.py
```

Посмотреть сообщение, ничего не отправляя:

```bash
DRY_RUN=1 TELEGRAM_BOT_TOKEN=x TELEGRAM_CHAT_ID=x python3 scripts/send_telegram.py
```

Открыть сайт:

```bash
python3 -m http.server 8765 --directory .
```

Зависимостей нет — только стандартная библиотека Python.

## Как считается индекс спроса

```
score = base × (1 − rain_penalty × weather_sensitivity)
        + события + праздник Таиланда + праздники за рубежом
```

- `base` — структурное положение направления
- `weather_sensitivity` — пляжные курорты ~0.45, Бангкок 0.15
- праздник Таиланда даёт +6 (внутренний спрос), зарубежные — до +4 суммарно

Это ориентир, а не измерение.

## events.json

Необязательный файл для того, что не приходит из календарей: фестивали
и заходы круизных лайнеров. Формат:

```json
{"from":"2026-07-30","to":"2026-08-02","scope":"pattaya","boost":18,
 "en":"Fireworks Festival","ru":"Фестиваль фейерверков"}
```

`scope` — `all` или id региона. Расписание круизов в Лаем Чабанг известно
на год вперёд с точным числом пассажиров — это лучший источник для пиковых дней.

## Файлы

```
index.html                      сайт, читает data.json
data.json                       пересобирается каждый день
events.json                     ручной календарь событий (необязательный)
scripts/build_data.py           сборщик данных
scripts/send_telegram.py        отправка сводки
.github/workflows/daily.yml     ежедневная задача
```

## Если сайт открыт, а data.json недоступен

Страница сама сходит в открытые API напрямую и покажет погоду и курс.
Пустой она не будет.
